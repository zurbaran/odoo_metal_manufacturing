Resolve the beneficiary of outgoing N43 transfers when OCA would
otherwise select the account holder from ``partner_name`` or
``partner_id``.

The addon returns a partner only. It neither implements reconciliation
nor creates invoices, payments or entries. Original bank fields are
untouched.

Configuration
=============

1. Install the addon alongside the OCA bank import and reconciliation
   addons.
2. Open the bank journal, Advanced Settings, N43 Beneficiary.
3. Enable Resolve N43 Beneficiary and add any additional account holder
   contacts. The company partner and commercial partners are included
   automatically.
4. Verify the bank layout and select the beneficiary complementary
   record. The described CajaMar layout uses 2305; this is not universal
   N43 semantics.
5. Keep ``n43_partner_search = none`` for the priority scenario.
6. Configure an OCA invoice matching model per supplier, restricted to
   the bank journal, outgoing payments and the expected partner. Set
   Match Partner, add that supplier to the partner list, and keep Auto
   Reconcile disabled.
7. Add a partner mapping matching the beneficiary name alone, for
   example ``(?i).*\bTEMPLAGLASS\b.*``, ``(?i).*\bVIDRIOS SALINAS\b.*``
   or ``(?i).*\bVBH\b.*``. OCA uses ``re.match``; a leading ``.*``
   permits a substring. The VBH mapping can explicitly target VBH Iberia
   despite the bank's alias.
8. To cover existing imports, enable Also Resolve Previously Imported
   Lines only on journals where the historical layout is known. The
   default extractor accepts CASHFra, CASHOferta and CASHProforma
   followed by a document reference and the destination name. Customize
   its named ``beneficiary`` group for other layouts. No reimport or
   destructive backfill is performed.

Mappings are evaluated against beneficiary-only text; put filters on
complete bank labels in the reconciliation model conditions, not the
mapping regex. Use mappings for supplier identity, never document
numbers.

Usage
=====

Open an un-reconciled imported outgoing transfer in the OCA
reconciliation UI. For the enabled journal, an account-holder result is
replaced with the unique beneficiary mapping that satisfies the original
model's applicability filters. Then OCA searches candidate journal items
using that partner and its own rules.

Incoming transfers, CORE direct debits, unrecognized transfer labels,
disabled journals, already reconciled lines and explicitly selected
third parties keep the upstream behavior. The import-time
``skip_retrieve_partner`` context is respected. Lookup does not change
the persisted partner or original bank text.

With ``n43_partner_search = all``, an imported account-holder partner is
corrected when resolving at reconciliation time. Other imported partners
remain trusted, so ``all`` is not recommended when bank heuristics can
select unrelated parties.

Known issues / Roadmap
======================

Unknown beneficiaries and conflicting applicable models return an empty
partner. Configure supplier models with Match Partner enabled so they
cannot suggest another supplier merely because a reference number
matches. Generic existing models that permit an empty partner retain
their upstream behavior and must be reviewed separately. This addon does
not impose a global safety policy on OCA.

Conflicts between models are rejected; within one model, the first
matching partner mapping follows OCA semantics. Keep mappings specific
and non-overlapping.

Structured concepts are retained for new imports. Historical lines
require explicit journal opt-in and a suitable extraction regex. Other
bank formats on that opted-in journal can also match this regex, so
verify the layout first.

The current fix remains limited to beneficiary resolution. Correct
partner identity does not by itself guarantee a suggestion: OCA's
account, date, currency, reference, residual and model conditions still
apply.
