N43 Beneficiary Partner Resolution

Resolve the beneficiary of outgoing N43 transfers when OCA would otherwise select the account holder from partner_name or partner_id.

The addon returns a partner only. It neither implements reconciliation nor creates invoices, payments or entries. Original bank fields are untouched.

Readable label and partner criteria support Starts with, Contains, Ends with, Exactly equals and advanced Python regular expressions. Plain text is stored with its options, rather than as a generated expression. Existing native conditions and mappings remain available. Ambiguous applicable mappings do not choose a partner by sequence.

Configuration

  1. Install the addon with its OCA dependencies. Enable Resolve N43 Beneficiary on the bank journal. The company contact is already an account holder; add other actual holder contacts only when needed.

  2. Check an original bank file before choosing the beneficiary concept. 2305 (selection 05) is the expected CajaMar layout, not universal N43 semantics. Keep N43 Partner Search = None for the priority scenario.

  3. Create an invoice matching reconciliation model per supplier, restricted to the journal, outgoing payments and expected partner. Require the partner. Leave Auto-validate disabled unless separately authorized.

  4. In Partner Mapping, select Label Match Type, enter Text, choose the case option and select the existing partner. For example:

    Match type Text Case-sensitive Partner
    Starts with COREMUTUA No Mutua Madrileña
    Contains TEMPLAGLASS No Templaglass S.L.
    Contains VIDRIOS SALINAS No Vidrios Salinas, S.L.
    Contains VBH No VBH Iberia, S.L.

  5. A Readable Label Condition is an additional condition on the COMPLETE bank label. It is not the beneficiary mapping. Set it only when needed. Native Contains / Not Contains remain suitable for existing ordinary conditions; no conversion is required to keep using them.

  6. For N43 outgoing transfers, partner mapping text is evaluated against the extracted BENEFICIARY NAME. Document numbers never identify the supplier. For ordinary CORE lines, mappings see the complete label. Notes remain an independent advanced Python condition and are ANDed with label matching.

  7. Starts with, Contains, Ends with and Exactly equals treat punctuation and special characters literally. Exactly equals does not accept extra text or a trailing newline. Advanced Python expressions retain re.match semantics; use .* explicitly when an advanced expression should match inside text. Advanced expressions control their own flags; the case checkbox is for text.

  8. Existing rules stay unchanged on upgrade. Simplify Recognized Prefix Rules is an explicit action: it recognizes only proven literal prefixes, preserving anchors, original expressions and historical casing semantics. Complex rules remain advanced. Clearing a readable match type restores its archived native condition; review the restored condition before saving.

  9. Historical N43 imports require Also Resolve Previously Imported Lines and a verified extraction pattern. No reimport or destructive backfill is needed.

Partner resolution does not enforce matching dates or exact payment amounts. OCA controls payment suggestions. Conflicting applicable mappings leave the partner unresolved; an explicitly selected third party is preserved.

Usage

Open an un-reconciled imported outgoing transfer in the OCA reconciliation UI. For the enabled journal, an account-holder result is replaced with the unique beneficiary mapping that satisfies the original model’s applicability filters. Then OCA searches candidate journal items using that partner and its own rules.

Incoming transfers, CORE direct debits, unrecognized transfer labels, disabled journals, already reconciled lines and explicitly selected third parties keep the upstream behavior. The import-time skip_retrieve_partner context is respected. Lookup does not change the persisted partner or original bank text.

With n43_partner_search = all, an imported account-holder partner is corrected when resolving at reconciliation time. Other imported partners remain trusted, so all is not recommended when bank heuristics can select unrelated parties.

See the migration guide and validation report before rollout.

Known issues / Roadmap

Validate complementary record 2305 with an original CajaMar N43 and complete a real pending-payment reconciliation on a database copy before production rollout. The regression suite uses controlled bank fixtures and posted payment items.

Date equality, payment candidate scoring and automatic reconciliation policy are outside partner identification. This addon does not implement them.
